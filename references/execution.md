# 实验运行、缓存与恢复

## 先让最小任务跑通

启动长实验前，用小输入接通加载、核心计算、结果保存和评价。重点检查数据格式、维度、设备、精度、接口、配置序列化和路径。学习模型再接通前向、损失、反向与状态恢复；系统或算法检查构建、调用及约束。

配置输出统一转换为可序列化值，例如把 Path 转成字符串。新增参数同时接入命令行、程序初始化、日志和必要的状态文件，先确认保存后可恢复。

数据、预处理、索引和状态格式采用独立版本。检查导入和初始化中的全局随机种子、线程数及环境变量设置，把实际运行配置显式记录。

## 本地和远程分工

远程下载受限、本地网络可用时，在本地准备公开资源，再传输到实验目录，核对文件大小和摘要。先确认已有缓存和镜像，复用可用数据。

区分代码、环境、原始输入、中间工件、可恢复状态、运行日志和结果。采用项目独立目录，保留构建与预处理的版本信息。

迁移服务器时，先确认以下依赖完整：

```text
代码快照 + 配置 + 输入清单
环境/构建信息 + 必要中间工件或重建脚本
可恢复状态 + 运行命令 + 结果记录
```

先在新环境复现一组旧结果，再启动后续实验。必要时重新构建平台相关二进制；大型工件可按记录重建，小型映射与配置随代码保存。

## 资源与任务安排

每轮启动前检查任务所需的 CPU、内存、GPU、存储或集群配额及用户给定的上限。将任务放到授权可用资源上，独立设置输出目录和运行配置。

根据计算特性选择资源。稀疏统计和轻量离线筛选可先评估 CPU 实现；并行数、数据加载及 BLAS/OpenMP 线程按机器负载调整。

任务使用可恢复的运行器或持久会话，保存配置、日志、进程信息和退出状态。支持断点的任务保存必要状态，学习模型包括优化器与随机状态。

等待结果优先使用完成通知、任务等待接口或完成标记。检查时读取本轮新增摘要和退出状态。任务结束后汇总结果，再安排下一轮。

## 把昂贵计算与低成本筛选分离

当上游计算固定、下游变化可独立评估时，保存中间结果用于离线筛选。例如复用预处理后的图、固定的执行轨迹或模型输出，快速比较参数和策略。

缓存与其依赖绑定：输入版本、实例顺序、实现、参数、状态与精度。依赖已变化时，重新计算相应部分。

缓存生成后，先抽取或完整复算锚点，比较逐实例输出。通过后再做批量搜索。分片缓存保留完整性标记和预期实例数，汇总时核对齐全。

离线筛选后，回到真实执行流程复核。测量性能时，分别注明冷缓存、热缓存及构建成本，采用与研究目标一致的状态。

表示变化会影响依赖链：

**输入或表示变化 → 构建/预处理 → 依赖状态 → 缓存 → 输出与测量。**

沿链条更新依赖。模型编码与 checkpoint 的兼容性细节见 [学习模型专项](learning-models.md)。

## 数值与公式对齐

数值实现重构后，以锚点结果检查行为。特别关注：

- sum 与 mean 对应的规模系数和单位。
- 条件、括号和运算顺序的实际作用范围。
- 初始化、参考状态与边界条件。
- 归一化和聚合采用的轴及数据范围。
- 数值精度、转换、容差及并列决策规则。

代数等价、数值容差与最终行为分别检查。小差异改变排序、搜索路径或终止条件时，保存差异实例并定位来源。等价重构先验证一致性，再测试新的机制。

## 保存可继续使用的结果

复用现有台账，并把关键工件串联起来：

| 工件 | 作用 |
|---|---|
| 运行配置与命令 | 重建同一实验 |
| 代码、输入与工件标识 | 确定结果来源 |
| 逐实例输出或测量 | 配对比较、分组与瓶颈分析 |
| 汇总指标文件 | 生成表格与图 |
| 选择记录 | 对应验证结果和采用配置 |
| 构建/状态工件与依赖清单 | 恢复执行或继续运行 |

研究计划记录当前最优方案、分支结论和下一步；论文事实表记录采用版本。为重要结果保留本地副本或可恢复归档。后续需要旧数据时，先查台账与输出，再判断是否重跑。

长任务交接时，给出正在运行的任务、已完成实验、当前位置和下一决策点，让后续工作从结果继续。
